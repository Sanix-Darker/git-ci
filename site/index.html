Git-CI

Run CI/CD pipelines locally before they reach CI

Parse and execute common CI workflow files directly from your repo, with filters, matrix expansion, and runner controls.

Core workflows

List

Inspect parsed jobs as tree output or structured JSON/YAML.

gci ls --format json | jq '.jobs | keys'

Run

Run selected jobs with filtering and dry-run safety.

gci run --only "test-*" --except "e2e-*" --dry-run --parallel

Validate

Run syntax checks and strict mode before real execution.

gci validate --strict -f .github/workflows/ci.yml

Runner & environment controls

Reproduce CI behavior with env injection, resource limits, and service-style networking.

gci run --docker --env-file .env --memory 2g --cpus 2 --network host

Install

Install gci in one of the following ways:

go install github.com/sanix-darker/git-ci/cmd@latest
git clone https://github.com/sanix-darker/git-ci.git && cd git-ci && make install
curl -L https://github.com/sanix-darker/git-ci/releases/latest/download/gci-$(uname -s)-$(uname -m) -o gci
chmod +x gci && sudo mv gci /usr/local/bin/gci

Quick start

Typical first run from any repo containing CI config:

git ci ls
git ci run
git ci run --job test --dry-run

Project tracking

We keep user stories and verification logs in a canonical workspace:

  • ~/tmp/git-ci/user-stories.md + user-stories.csv (features and status)
  • ~/tmp/git-ci/verification-loop.md (checks run + pass/fail notes)
  • Errors and follow-up fixes are recorded before the next release pass
