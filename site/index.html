Git-CI

Run CI/CD pipelines locally

Execute GitHub, GitLab, CircleCI, Drone, or Travis workflows directly from your repository using bash, Docker, or Podman.

GitHub Documentation

Core Commands

Run

Parse and execute pipelines from detected CI files with filtering, matrix expansion, and parallel scheduling.

gci run --debug --parallel --max-parallel 4 --dry-run

List

Inspect parsed jobs as tree output or machine-readable JSON/YAML.

gci ls --format json | jq '.jobs | keys'

Validate

Run strict syntax checks before execution and detect provider/runner mismatches early.

gci validate --strict -f .github/workflows/ci.yml

Environment & Runner Controls

Use --env, --env-file, timeouts, memory, CPU, volumes, and network settings to reproduce production-like runs.

gci run --env-file .env --memory 2g --cpus 2 --network host

What is git-ci?

git-ci runs common CI/CD pipeline definitions locally so you can iterate faster before pushing to a shared CI runner. It supports GitHub and GitLab workflows with parser compatibility for CircleCI, Drone, Travis and more via file discovery.

  • Parse CI pipelines and inspect jobs/stages before execution
  • Run workflows with Bash, Docker, or Podman
  • Validate configuration locally with strict checks
  • Generate starter pipelines for GitHub and GitLab

Install

Install locally to get gci command access quickly.

go install github.com/sanix-darker/git-ci/cmd@latest
make install
curl -L https://github.com/sanix-darker/git-ci/releases/latest/download/gci-$(uname -s)-$(uname -m) -o gci
chmod +x gci
sudo mv gci /usr/local/bin/
